# Translations (i18n)

Decision: [ADR 0010](../adr/0010-ui-translations.md). Code: `crates/ss-app/src/i18n.rs`.

## 1. Files

```
crates/ss-app/
  i18n.toml                 ← fallback language "en", domain "openseries" (read by fl!)
  i18n/
    en/openseries.ftl       ← source language, fallback for missing messages
    de/openseries.ftl
    <tag>/openseries.ftl    ← any BCP 47 tag: fr, pt-BR, zh-Hans, …
<config dir>/i18n/<tag>/openseries.ftl   ← user translations, loaded at start-up
```

The config dir is the folder holding `config.json` (macOS `~/Library/Application Support/OpenSeries`,
Windows `%APPDATA%\OpenSeries`).

Each file is [Fluent](https://projectfluent.org/fluent/guide/) and starts with
`language-name = <the language's name in itself>` (shown in Settings → Language). Sections
(`## …`) follow the app's pages.

## 2. Choosing the language

1. `app.language` in the config (`"de"`); Settings → General → Language writes it.
2. Unset ("System default"): the OS's preferred languages (`sys-locale`), negotiated against the
   available ones (`de-AT` → `de`).
3. Nothing matches: English.

Messages a translation lacks fall back to English one by one. A change in Settings applies at
the next frame; the tray menu re-labels itself.

## 3. Lookup sources, in priority order

1. `<config dir>/i18n/<tag>/openseries.ftl` (user file)
2. the embedded `i18n/<tag>/openseries.ftl`
3. English

So a user file can fix single messages of a built-in language, or add a new language. Folders
whose name is not a valid language tag are ignored.

## 4. In code

```rust
use crate::i18n::tr;

ui.label(tr!("settings-language"));
tr!("tray-device-battery", device = name, percent = level.percent())
```

- `tr!` wraps `i18n_embed_fl::fl!`: unknown ids and arguments are compile errors (checked against
  `i18n/en/openseries.ftl`). After adding a message, `touch` the `.rs` file if the macro still
  reports it missing (it does not track the `.ftl`).
- Ids are kebab-case with a page prefix (`device-`, `mix-`, `mic-`, `settings-`, …).
- Dynamic ids (device feature and option labels from drivers) use `i18n::lookup(id)`, which
  returns `None` when no translation defines the id; the UI then shows the driver's English text.
- Not translated: log output, errors from lower crates (the wording around them is), product and
  device names, the licence list, the developer tools.

Tests (`i18n::tests`): every built-in language parses, names itself, and has exactly the ids of
English.

## 5. Adding a language

**Without building the app:** copy `i18n/en/openseries.ftl` from the repository to
`<config dir>/i18n/<tag>/openseries.ftl`, translate the values, restart OpenSeries and pick the
language in Settings. Keep ids and `{ $arguments }` as they are.

**Into the app (pull request):** put the file at `crates/ss-app/i18n/<tag>/openseries.ftl`; it must
contain every message of English (`cargo test -p ss-app i18n` lists missing ones). No code change.

## 6. Limits

- egui's bundled fonts cover Latin, Greek and Cyrillic; scripts like CJK or Arabic need a font
  fallback in `ui/theme.rs` first, and right-to-left layout is not supported.
- Numbers and units are formatted in code (no locale-specific decimal separators yet).
